- **GAP found**: no numeric score threshold is ever stated. The three grade bands (`production-ready`, `needs-work`, `rewrite`) appear at SKILL.md:256 and 290 but the score ranges that map to each band are never given anywhere in SKILL.md or `references/evaluation-frameworks.md` (grep for grade/threshold across both files returns only the qualitative band names and unrelated CI-threshold code samples for a different quality-gate system entirely, e.g. `min-accuracy 0.90` in a Python CI snippet at evaluation-frameworks.md:562, which is a different scoring system for evaluating LLM outputs generally, not this rubric). This means `--ship-below-threshold`'s trigger condition ("below threshold") is operationally undefined as a number — it can only be interpreted by the grade label, not a score cutoff.

**RATE output contract** (SKILL.md:87-98, Section 2 lines 249-296):
- RATE mode **always writes** `NAME.rating.md` (scorecard + test cases + fixes).
- RATE mode **also writes** `NAME.remediated.md` — and the doc is explicit that remediations are APPLIED, not merely advised: Section 2.1 (lines 279-292) is titled "Remediation application (mandatory)" and states "A rating that stops at the scorecard is unfinished. - **Does the skill require remediations to be APPLIED?** Yes, unconditionally, unless `--report-only` is passed (which per the Authorization Engine table, line 80, requires "explicit user consent" to skip file output — i.e. skipping application is the exception path requiring explicit opt-in, not the default). Default behavior with no flags is: rate + write rating file + apply fixes + write remediated file + re-score. This matches `commands/rate-prompt.md:10` "Unexecuted suggestions are UNVERIFIED — remediate, do not merely advise."

## 3. Rubric red-team

The 100-point 7-dimension rubric (`prompt-forge/SKILL.md:257-265`):

| Dimension | Points |
|---|---|
| Clarity | /20 |
| Specificity | /15 |
| Structure | /15 |
| Output contract | /15 |
| Edge-case cover | /15 |
| Testability | /10 |
| Token efficiency | /10 |
| **Sum** | **100** |

- **Do the weights sum to 100?** Yes: 20+15+15+15+15+10+10 = 100. Verified by direct arithmetic on the exact numbers as written in the table.
- **Do any two dimensions score the same property?** One EXPLICIT, self-documented overlap exists: SKILL.md:276-277 states "Structure deductions reference the 0.5 tag table explicitly (missing `output_contract` is a Structure deduction AND an Output-contract deduction)". This means a single defect (a missing `output_contract` XML tag) is penalized under BOTH the Structure (/15) dimension AND the Output contract (/15) dimension simultaneously — a double-count against the same underlying property (presence of the `output_contract` tag), worth up to 30 of the 100 points combined for one defect. This is not an inferred ambiguity; it is written into the rubric's own rules section as intentional/expected behavior, but it is nonetheless a genuine scoring redundancy: the same evidence (one missing tag) can move two separate dimension scores.
- No other dimension pairs were found to score identically overlapping properties on inspection of the dimension names and their described scope (Clarity=organization/comprehensibility, Specificity=concreteness of requirements, Edge-case cover=failure-mode handling, Testability=defined success metric, Token efficiency=verbosity) — these five appear to target genuinely distinct properties with no documented overlap.
- **Is any threshold unreachable?** No score-based threshold is defined numerically at all (see Section 2 gap above), so "unreachable" cannot be evaluated against a number — but this itself is a finding: an undefined threshold cannot be proven reachable OR unreachable; it's an open gap, not a contradiction, and is reported as a gap rather than a contradiction to avoid overclaiming.
- **Method used:** read `SKILL.md` end to end (lines 1-361, with two targeted re-reads for the flag table at 155-179 and RATE section at 249-296), read `references/evaluation-frameworks.md` targeted grep for grade/threshold keywords (that reference file documents a DIFFERENT, more elaborate CI-based evaluation system for general LLM test suites — 1-5 point sub-scales, CI YAML thresholds like `min-accuracy 0.90` — which is NOT the same 100-point rubric quoted in SKILL.md's RATE section; the two coexist in the skill's reference material as separate frameworks, and SKILL.md's own inline 100-point table is the one actually used by the `rate` command per its Section 2 text).
