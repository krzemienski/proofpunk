## 3. Defect taxonomy

Four classes asserted by the brief, validated against the record. All four are supported. A fifth class is added.

### Class 1 — a harness that structurally cannot fail (i.e. it always reports success regardless of the underlying defect)

**Supported. ≥2 instances:**

- **`5e5150b`**: `tools/dry-run-install.sh` was *documented* in `tools/AGENTS.md` as the installer dry-run harness but its own `grep -c` count of invocations of `tools/proofpunk-install.sh` was **0** — it never called the real installer at all. "Zero installer coverage is how three green gates coexisted with five real defects."
- **`8718561`**: proves this class directly with a controlled before/after. Same mutated-hooks-dir input driven against the OLD harness (`96d91d6`, rc=0 — "structurally could not detect the defect it was meant to catch") vs the NEW harness (HEAD, rc=1). Same input, opposite verdict — direct proof the old harness was structurally incapable of failing.
- **`2047a9f`**: `test-hooks.sh` "grepped for substrings instead of parsing," so it passed on a payload that was malformed JSON (missing comma) that a real host silently dropped. Fixed to `json.load` + assert on `hookSpecificOutput`; mutation-checked (reintroducing the missing comma in a sandbox now yields rc=1).
- **`a41591a`**: `fresh_evidence.py` validate "returned OK on zero-artifact runs, unsealed runs, and equal-size substitution" — three distinct ways the validator could not fail. Rebuilt as a v2 SHA-256 inventory with strict hex and traversal rejection.

### Class 2 — a hardcoded list drifting from its canonical source

**Supported. ≥2 instances:**

- **`93c479d`**: "Hardcoded 'known baseline size = 29' REMOVED; classification now derived from a provenance-header regex plus a live glob of references/."
- **`b4bd03a`**: `verify-orchestration.py`'s expected leaf set was a hardcoded list, "so declaring a real edge broke the check while the graph stayed correct. It now derives the set from what each skill declares." The commit calls this out explicitly as a *pattern*: "Derive, never restate — the same root cause behind most of this backlog."
- **`a41591a`**: the installer hardcoded its own hook list, so the shipped tree silently drifted from the `hooks.json` manifest (6 of 7 scripts copied, 4 of 6 events registered). Fixed by deriving both lists from `hooks.json` directly.
- **`207e041`**: `tools/build-site.py:311` hardcoded the literal string `/proofpunk:cook` (a command removed at v2.0.0) into the generator — "every regeneration reproduced it," i.e. the hardcoding was self-perpetuating across every future build until fixed at the source.
- **`2047a9f`**: `build-site.py`'s skill-count assertion was hardcoded, replaced with one derived from the skills glob.

### Class 3 — a component shipped but never registered

**Supported. ≥2 instances:**

- **`99c72fb`**: `evidence-guard.sh` "has therefore shipped on disk but never registered in every `--hooks` install since it was written" — root cause was that the settings.json merge treated idempotency as per-EVENT rather than per-command, so once any script for an event was present, every sibling for that event silently returned "already present" and was skipped. Fixed by making idempotency per-command. The commit explicitly names the detection gap: "test-installer.sh gains group 8, which reads the produced settings.json — the only vantage point from which a copied-but-unregistered hook is visible. **Plugin-side tests structurally cannot see it.**"
- **`a41591a`**: `session-start.sh` was "silently missing" from installed trees (6 of 7 scripts copied) because the installer's hardcoded hook list (Class 2 defect, same commit) omitted it.
