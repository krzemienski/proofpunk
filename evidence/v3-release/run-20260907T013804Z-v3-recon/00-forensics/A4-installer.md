## APPEND 1 — Task item 1 RESOLVED: exact bundler mismap mechanism (Main's request)

**Reproduction (scratch dir, `--no-verify` to see raw bundled content before auto-fix runs):**
```
bash tools/proofpunk-install.sh --source-dir "$(pwd)" --dir <scratch>/dst --no-doctrine --no-verify --only end-user-testing
```
rc=0. `<scratch>/dst/end-user-testing/references/` contains 6 files: `end-user-actor.md`, `evidence-contract.md`, `platform-routing.md`, `preflight-checks.md`, `run-trace-schema.md`, `severity-model.md`. **`severity-model.md` IS bundled as a sibling** — this proves the auto-fix's later "fix" (re-copying it) is a no-op against an already-present file, not a genuine repair.

**Confirmed byte-identical citation text, source vs installed:**
- Source: `plugins/proofpunk/references/run-trace-schema.md:269` — `` Proofpunk uses (`references/severity-model.md`). ``
- Installed (no-verify): `<scratch>/dst/end-user-testing/references/run-trace-schema.md:269` — IDENTICAL text, byte-for-byte, `references/severity-model.md` still present. Confirms depth-normalization NEVER touched this bundled copy of the file — the sed pass at 296-300 ran once before the file was bundled and does not run again.

**Root mechanism, traced step by step through `tools/proofpunk-install.sh`:**

1. `tools/proofpunk-install.sh:283` — raw `tar` copy of the skill dir. `dst/SKILL.md` (end-user-testing's own file) at this point still has its original `../../references/run-trace-schema.md` citation.
2. `tools/proofpunk-install.sh:288-290` — top-level sed pass over **all** `*.md` under `dst` (recursive), collapsing `../../references/` → `references/`. This runs on `dst/SKILL.md` (rewriting its citation to `references/run-trace-schema.md`) but at this point in execution `dst/references/` **does not exist yet** — nothing has been bundled in.
3. `tools/proofpunk-install.sh:296-300` (`if [ -d "$dst/references" ]`) — the depth-normalization pass that rewrites `references/X` down to bare `X` for files **already inside** `dst/references/`. This check is FALSE right now (directory doesn't exist yet) — this block never fires for this skill at this point, and critically, **it never fires again later either** — it sits BEFORE the fixed-point `while` loop at 306-322 and is not inside it, so it only ever gets one chance, before any bundled files exist.
4. `tools/proofpunk-install.sh:301-323` — the fixed-point bundling loop. `mkdir -p "$dst/references"` (line 302) now creates the directory. Iterating `$REFS_SRC/*` in alphabetical order: `run-trace-schema.md` (r) is checked before `severity-model.md` (s) in the same pass. `run-trace-schema.md` matches the grep against `dst/SKILL.md`'s now-rewritten `references/run-trace-schema.md` citation (line 316) and gets `cp`'d **verbatim from `$REFS_SRC`** into `dst/references/run-trace-schema.md` — carrying its own internal `` `references/severity-model.md` `` citation UNCHANGED, because the depth-normalization step that would have fixed it (step 3) already ran and does not run again. **This is the propagation point: copied refs are not re-normalized, so the unresolved nested `references/` prefix rides along into the bundled copy verify will later inspect.**
5. **Same while-loop pass, same iteration**: when the loop reaches `name=severity-model.md`, the grep at line 316 now searches all of `dst` INCLUDING the just-copied `dst/references/run-trace-schema.md` (added earlier in this same pass) — finds the literal string `references/severity-model.md` inside it — matches — copies `severity-model.md` too. This is legitimate fixed-point closure per the design comment at 303-305, and it is why `severity-model.md` IS present as a sibling by the time verify runs (confirmed in the repro above).
6. **Verify step, separate python subprocess, `tools/proofpunk-install.sh:613-687`, called once per skill AFTER all skills have finished installing.** `find_bad()` (defined 626-662) walks `dst/end-user-testing/references/run-trace-schema.md`. The citation regex at `tools/proofpunk-install.sh:638-639` matches `t = 'references/severity-model.md'` (the un-normalized text carried in from step 4). `dp = dst/end-user-testing/references` (the directory containing `run-trace-schema.md`). `cands = [os.path.join(dp, t)]` = `.../end-user-testing/references/references/severity-model.md` — a **doubled path that never exists**.
7. **The exact bug — `tools/proofpunk-install.sh:649-652`:** the sibling-resolution fallback that would append the candidate `os.path.join(os.path.dirname(dp), t)` is gated by `not t.startswith('references/')`. Because `t` here IS `'references/severity-model.md'` (still carrying its un-normalized prefix from step 4), this condition is **false**, so the fallback candidate is never added to `cands`. The real sibling file `dst/end-user-testing/references/severity-model.md` (which DOES exist per step 5) is never checked. `os.path.exists` fails on the only candidate → `bad.append(('run-trace-schema.md', 'references/severity-model.md', dp))`.
8. **Auto-fix, `tools/proofpunk-install.sh:664-682`:** for this `bad` tuple, `base = os.path.basename(t)` = `'severity-model.md'` (basename silently strips the very `references/` prefix that caused the miss). `src = os.path.join(refs_src, base)` exists in `$REFS_SRC` → `shutil.copy2` re-copies it into `dst/end-user-testing/references/severity-model.md` — a **no-op**, since that file is already there byte-identical (confirmed in the repro above). `repaired += 1` is incremented for a copy that changed nothing.
9. `still = find_bad(dst)` re-runs the identical check. `run-trace-schema.md`'s citation text was never touched by the "fix" (the fix only ever re-copies `severity-model.md`, never edits `run-trace-schema.md`'s prose). `still` is non-empty, identical to `bad`. Lines 679-681 fire: `print(f'  ✗ {name}: BROKEN refs after auto-fix: {[(f, t) for f, t, _ in still][:5]}')` then `sys.exit(1)` — **this is the literal source of the F-002 log line** `✗ end-user-testing: BROKEN refs after auto-fix: [('run-trace-schema.md', 'references/severity-model.md')]`.

**Answer to Main's question ("why does an unresolved citation get mapped onto a different reference rather than failing with its own name"):** It does NOT actually resolve to a different reference — `basename()` at step 8 just extracts `severity-model.md` from the tail of the un-normalized citation string `references/severity-model.md`, so the auto-fix's log tuple *looks like* it's blaming `severity-model.md`, but the auto-fix is really trying (and failing) to repair `run-trace-schema.md`'s citation. Root cause is the ordering bug at steps 2-4 (depth-normalization runs once, BEFORE the fixed-point bundling loop, instead of after each bundling pass) combined with the `startswith('references/')` exclusion at line 651 in `find_bad()`'s sibling fallback, which together mean: any newly-bundled reference file that itself cites another shared reference by its repo-relative form (`references/X.md`) will carry that unresolved form straight through to verify, and verify's own sibling-fallback logic is specifically blind to citations still wearing that prefix.

**Fix would touch (NOT applying, per Main's Phase-5-only instruction):** either (a) re-run the depth-normalization block (296-300) after each bundling pass inside the `while` loop at 301-323 rather than once before it, or (b) drop the `not t.startswith('references/')` exclusion at line 651 so the sibling fallback candidate is always considered for citations found inside `references/*.md` files, or (c) both. This finding does not decide which fix is correct — only Phase 5 is authorized to apply and adopt a proposal.

### Complete `settings.json` merge logic (`tools/proofpunk-install.sh:435-489`)

1. **Load-or-init** (`:439-449`): `os.makedirs(..., exist_ok=True)` creates the parent dir. If the file exists, attempt `json.load`. **Corrupt-JSON handling**: on `JSONDecodeError`, the corrupt original is preserved via `shutil.copy2` to `settings_path + ".corrupt-" + str(int(time.time()))`, a `WARN` names the backup path, and `settings` resets to `{}` — never silently discarded, never a crash.
2. **Other top-level keys preserved**: `hooks = settings.setdefault("hooks", {})` (`:450`) — only the `"hooks"` sub-key is ever mutated; a user's `permissions`, `model`, or other config keys are untouched.
3. **Per-command idempotency, `ensure()`** (`:452-467`): for each `(event, command, matcher, timeout)`, scans every existing entry's every hook `command` for one containing `.proofpunk/hooks` AND matching basename (`command.rsplit("/", 1)[-1]`) — if found, returns `"already present"` (no append). Else appends `{"hooks": [{"type": "command", "command": command, "timeout": timeout}]}` (+ `"matcher"` if given), returns `"added"`. This is the `99c72fb` fix — idempotency is per-COMMAND, not per-event, per the comment at `:454-456`; confirmed live in APPEND 4(ii).
4. **Iteration source is `hooks.json` alone** (`:468-481`): loads `hooks.json` fresh, iterates `spec.get("hooks", spec).items()`, then every matcher-group's every hook ending in `.sh` (non-`.sh` commands explicitly skipped at `:477-478`). Builds a `label` — bare event name if exactly one matcher with exactly one hook, else `"{event}:{script_without_.sh}"` (`:479`) — the source of labels like `PreToolUse:no-test-files`.
5. **Pre-write backup of the WHOLE file** (`:482-483`): if `settings_path` already existed, unconditional `shutil.copy2` to `settings_path + ".bak"` BEFORE overwrite — distinct from the corrupt-JSON sidecar in step 1; a valid pre-existing file still gets a `.bak` of its pre-merge state.
6. **Final write** (`:484-485`): `json.dump(settings, f, indent=2)` full overwrite (non-hooks keys preserved, hooks merged).
7. **Output** (`:486-488`): one line per `(label, result)` plus settings path — source of the `SessionStart: added` / `already present` lines seen in every re-drive above.
