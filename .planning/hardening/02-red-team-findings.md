## SECURITY (8)

- SECURITY | CRITICAL | SEC-1 | where: P3 plugin-root resolution contract | why_it_matters: Root is any tree with skills/+themes/, the runner is chosen by glob, and authenticity is `--help` exit 0, so a planted checkout wins discovery and executes as the trusted evidence/theme/plugin supplier.
- SECURITY | CRITICAL | SEC-2 | where: evidence_requirements `script -qfc` + P9 fuzz_paste/keys/resize + P10 SSH matrix | why_it_matters: Driver is a shell `-c` string under paste/key storms and an SSH hop with no inner/outer PTY isolation, no CSI/OSC filter on captured streams replayed to the operator TTY, and no ban on fuzz delivering SIGINT/`exit` to the wrapper.
- SECURITY | HIGH | SEC-3 | where: P3 ≤1s watcher + P7 Screen 4 self-hosting + evidence_requirements non-empty bytes | why_it_matters: Watcher plus in-app artifact list/validate have no run-dir confinement, symlink reject, or untrusted name/content rendering rule, while PASS only requires >0 bytes, so a planted path or ANSI/OSC payload in e2e-evidence/run-* is ingested and displayed.
- SECURITY | HIGH | SEC-4 | where: no_touch permission prompts never auto-allow + P5 permission modal + P9 real-PTY storms | why_it_matters: Never-auto-allow binds the builder, not the product; P5 only requires a modal exist, while P9 key/paste storms can deliver Allow into that modal with no invariant that fuzz must not approve tools.
- SECURITY | HIGH | SEC-5 | where: P3 fresh_evidence.py runner + scope touch invocation-only + evidence_requirements subprocess | why_it_matters: Plan names a glob-resolved subprocess and invocation-only use but never binds explicit argv (no shell strings), an env allowlist, or a resolved-path pin, so the matched script runs with the TUI's cwd/env.
- SECURITY | HIGH | SEC-6 | where: no_touch failed secret scans + P7 blocked-then-clean seal + evidence_requirements PTY screenshots + scope touch git init/commit | why_it_matters: Secret control is don't-silently-override plus an inject-then-clean ritual; no scanner, no scan of script typescripts/screenshots/inspector JSON/SSH captures, while local git commit is in-scope so leaks persist as committed evidence.
- SECURITY | HIGH | SEC-7 | where: scope touch default --max-budget + stop_conditions budget-cap consent + P4/P8 observational metrics + P5 subagent spawn + P10 30-min run | why_it_matters: Cap is an unspecified default the builder must not exceed without consent; metrics are display/export only; nothing hard-stops the SDK or aggregates nested subagent spend across P0/P3/P5/P10 sessions.
- SECURITY | HIGH | SEC-8 | where: P3 cwd pinned to product repo (evidence bridge) vs P0/P3/P5 real SDK sessions + scope touch new repo | why_it_matters: Cwd pin is evidence-subprocess only; SDK/subagent project-root confinement is unspecified, so tool writes and plugin-hook side effects are not project-rooted while the session is still treated as in-scope.

## FAILURE-MODES (8)

- FAILURE-MODES | CRITICAL | FM-1 | where: stop_conditions + every Verify | why_it_matters: Stop list has UNVERIFIED/FAIL/missing-root/budget-consent but no wall-clock, SDK-connect, or wait-for-state deadline, so a hung Claude CLI, never-arriving ResultMessage, or observe-before-act that never matches leaves the phase gate blocked with no abort.
- FAILURE-MODES | CRITICAL | FM-2 | where: P3 bridge/sdk.py | why_it_matters: Single-owner receive_messages() task is the only SDK I/O path and is unspecified as off-loop, so its stall starves Textual (p95 16ms dies) and CLI crash only freezes+resume-same-session-id with no backoff, failed-resume path, orphan-CLI reap, or fate for the command queue (Interrupt/Send lost vs replayed).
- FAILURE-MODES | HIGH | FM-3 | where: integrity of event pipeline | why_it_matters: Coalesce-token-deltas-never-drop-control has no numeric depth, no overflow-beyond-coalesce, and an unbounded sole-source event log, so sustained burst either OOMs, misses RSS ≤10MB/30min, or coalesces deltas then fails 'zero dropped stream events'.
- FAILURE-modes | HIGH | FM-4 | where: P8 Screen 5; P10 30-min run | why_it_matters: A live 30-min SDK session can hit --max-budget, rate-limit, permission-modal stall (never auto-allow), or thermal/CI variance with no unattended mode, retry/discard rule, or mid-run abort, so one flake re-runs the whole gate from prerequisites.
- FAILURE-MODES | HIGH | FM-5 | where: P3 plugin-root contract | why_it_matters: Root-iff-skills/+themes/ plus --help exit 0 does not rank multiple matching installs (cache vs marketplace vs checkout) and a help-only stub passes, so the evidence/theme/hook stack can bind the wrong tree while cwd(product) vs SDK --project remains a split write-watch path.
- FAILURE-MODES | HIGH | FM-6 | where: P5 §7 S1 interrupt + permission modal; no_touch never auto-allow | why_it_matters: Interrupt during a pending permission modal, and keystrokes aimed at interrupt vs modal confirm, have no sequencing or focus rule, so Verify either deadlocks on a human prompt with no wait bound or applies the wrong allow/deny after resume.
- FAILURE-MODES | HIGH | FM-7 | where: P3 watcher; P7/P10 Screen 4 self-host | why_it_matters: Watcher death, FSEvents coalescing, or SDK-bridge death while the watcher keeps writing is unspecified, leaving Screen 4 live against a frozen/dead session (split-brain) and seal/next-step/validate racing a ≤1s poll with no debounce or failover.
- FAILURE-MODES | HIGH | FM-8 | where: driver/PTY | why_it_matters: No driver/PTY timeout or SIGWINCH resync, P6 either double-drives one TUI (forbidden) or collides two SDK/evidence sessions, and BSD script -qfc vs Linux SSH script flags desync the harness so storms and matrix runs hang or false-fail.
